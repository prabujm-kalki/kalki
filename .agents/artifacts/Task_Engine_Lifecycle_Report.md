# Purchasing Activity & Task Engine Lifecycle Report

Based on a deep analysis of your database (`purchase_schedules`, `task_instances`) and the frontend UI logic, here is the complete explanation of what is happening in your Recent Activity feed.

### The Complete Lifecycle: How it Works
1. **Configuration (`purchase_schedules`):** The user defines a routine in the Configuration UI (e.g., Check Sakthi Masala stock every day at 11:15).
2. **Trigger (Background Cron Job):** A background service (the Task Engine) constantly checks the time against the configured schedules.
3. **Creation (`task_instances`):** When the time hits 11:15, the Task Engine creates an actual "ticket" or "instance" of that task in the database and assigns it to a specific Role (e.g., Cashier).
4. **Execution:** The assigned user completes the task. If the task requires review, its status changes to `audit_pending` (Awaiting Audit) instead of just "closed".
5. **Escalation Engine:** If an auditor (Manager) ignores the pending audit for too long (e.g., > 24 hours), the Task Engine automatically wakes up, escalates the audit level (Level 1 -> 2 -> 3), and updates the task's timestamp.

### Answering Your Questions

**1. Why is Sakthi Masala running even though it is not visible in the current configuration?**
- **What Happened:** The Sakthi Masala task (TASK-C32C5) was originally configured and triggered successfully by the Task Engine on **October 4th**.
- **Why it is missing:** Sometime *after* October 4th, the Sakthi Masala schedule was either deactivated or deleted from the Configuration page. 
- **The rule:** Deleting a schedule only stops *future* tasks from being generated. It does **not** delete historical tasks that were already generated and are currently sitting in someone's inbox waiting to be processed or audited.

**2. Why did it appear in "Recent Activity" today (Oct 6th) if it was triggered on Oct 4th?**
- The Recent Activity feed sorts by the `updated_at` timestamp.
- The Sakthi Masala task was sitting in the "Awaiting Audit" queue since Oct 4th. Because the auditor ignored it for more than 24 hours, the Task Engine woke up today (Oct 6th), escalated the task to **Audit Level 3**, and appended the warning: `"Auditor ignored task for > 24 hours. Escalated to Level 3"`.
- This automated escalation updated the timestamp to today, bumping it to the very top of your Recent Activity feed.

**3. Why are the three "Task Engine" tasks appearing and waiting for audit?**
- **What they are:** These are automated background system tasks (or backend test routines) generated by the system.
- **Why they say "Task Engine":** In the UI code (`RecentActivityFeed.tsx`), the "Entity" column looks for a `vendorName` or `title` inside the task's data. If the task is a generic system task and doesn't belong to a specific Vendor, the UI gracefully defaults to displaying "Task Engine".
- **Why they are waiting for audit:** Just like the vendor tasks, these system tasks were completed but flagged for human review. They are currently stuck in the `audit_pending` state, and the escalation engine is continually bumping their timestamps as they get ignored by managers.

### Summary Relationship
1. **Routines** are the blueprints.
2. **Task Engine** is the factory that reads blueprints and generates live tasks at the correct time.
3. **Task Execution** is when human workers complete the tasks.
4. **Audits & Escalations** ensure tasks don't get ignored. If they do, the Engine artificially updates them to trigger alarms.
5. **Recent Activity** simply blindly lists any task that was *created* or *updated* recently. Because the Engine is actively escalating ignored tasks, they flood the Recent Activity feed, making it look like they are running anew, when in reality, they are old tasks screaming for an auditor's attention!
